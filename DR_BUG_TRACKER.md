# DR Replication Bug Tracker

This tracks bugs found while validating the DR replication PoC. Keep DR protocol
bugs separate from baseline HA/OpenBao issues so the changes can be split into
independent worktrees before review.

| DR-008 | DR failover/lineage | Fixed in current PoC tree | `../openbao-dr-promotion-lineage-fence` | A promoted standalone cluster could be explicitly re-enabled as a secondary using a stale activation token from the pre-promotion old primary lineage. `EnableSecondary` now rejects tokens matching the last promotion's old primary cluster ID or old relationship ID, while still allowing fresh post-promotion lineage. |
| DR-009 | DR bootstrap/API transport | Fixed in current PoC tree | `../openbao-dr-api-addr-normalization` | Secondary bootstrap and credential rotation reused the cluster-transport address normalizer for primary API addresses, which rewrote explicit `http://` API listeners to `https://` and broke repo-local TLS-disabled HA testing. API address normalization now preserves explicit schemes, defaults bare API addresses to HTTPS, and only requires primary API CA material for HTTPS API endpoints. |
| DR-010 | DR reconnect/HA | Fixed in current PoC tree | `../openbao-dr-secondary-ha-reconnect-ring` | Secondary stream/reconcile/resnapshot transport failures trusted the last heartbeat leader hint and could pin reconnects to a stale standby after HA step-down. Transport failures now return plain reconnect errors so the controller rotates through configured primary addresses; structured DR redirects remain the direct leader path. |
| DR-011 | DR bootstrap/security | Fixed in current PoC tree | `../openbao-dr-bootstrap-token-verifier` | Pending relationship records persisted the bootstrap bearer token directly. New relationships now persist only a relationship-bound verifier hash, legacy plaintext pending records are migrated on load, and terminal success/failure/revocation clears both plaintext and verifier fields. |
| DR-012 | DR endpoint/audit boundary | Fixed in current PoC tree | `../openbao-dr-endpoint-audit-boundary` | Regression coverage now locks the exact unauthenticated DR HTTP surface, root-protected DR admin surface, sensitive schema metadata for bootstrap/rotation material, and default audit HMAC redaction for raw bootstrap tokens, secondary certificates, and rotation signatures. |
| DR-013 | DR response disclosure boundary | Fixed in current PoC tree | `../openbao-dr-response-disclosure-boundary` | Relationship list/status responses now share an explicit allowlisted response builder, and regression tests prove broad status and relationship responses do not expose local DR config secrets, stale promotion lineage identifiers, bootstrap verifier material, certificate bytes, pending/previous certificate fingerprints, or pending rotation operation IDs. |
| DR-014 | DR unauthenticated error-oracle hardening | Fixed in current PoC tree | `../openbao-dr-unauth-error-oracles` | Bootstrap registration and credential-rotation endpoints now keep request-shape errors specific but return generic public errors for relationship lookup, token/signature validation, relationship state, lockout, stale lineage, duplicate fingerprint, and pending-rotation failures; detailed reasons are logged server-side and remain available through root-protected relationship status. |
| DR-015 | DR gRPC data-plane authz | Fixed in current PoC tree | `../openbao-dr-grpc-data-plane-authz` | Systematic regression coverage now proves StreamChanges, RequestCheckpoint, Heartbeat, ExchangeDirtyBitmap, checkpoint-scoped checksum/digest/fetch RPCs, and SyncKeyring deny missing peer identity, mismatched certificate fingerprints, mismatched relationships, and revoked relationships where applicable. Checkpoint-scoped RPCs now carry `relationship_id`, authorize it before checkpoint lookup, and require the checkpoint's persisted relationship ID to match. |
| DR-016 | DR SyncKeyring crypto binding | Fixed in current PoC tree | `../openbao-dr-synckeyring-crypto-binding` | `SyncKeyring` now validates malformed requests without activating the relationship, serializes keyring sync, allows only registered relationships, marks the relationship active only after successful wrapping, and denies replay after activation. Regression coverage unwraps the primary response with relationship/cluster/secondary-fingerprint/primary-identity AAD and verifies fresh server nonce, server ephemeral key, GCM IV, and ciphertext for repeated client nonces. |
| DR-017 | DR unauthenticated resource-exhaustion hardening | Fixed in current PoC tree | `../openbao-dr-unauth-resource-exhaustion` | Credential rotation now performs cheap shape, timestamp, size, relationship-state, and pending-operation checks before parsing attacker-supplied certificates, and verifies rotation signatures with stored current or pending certificate material where possible. Regression coverage proves registered relationships and missing pending confirmations reject malformed certificate material without invoking x509 parsing, while the normal two-phase rotation path still succeeds. |
| DR-018 | DR revocation semantics | Fixed in current PoC tree | `../openbao-dr-revocation-fail-closed` | Primary RPCs that can return sensitive material or stream multiple batches now re-check relationship authorization before returning or continuing after work. `SyncKeyring` fails closed if revocation lands during root-key wrapping, `FetchEntries` stops after an in-flight revoke instead of continuing to stream checkpoint data, and revoking a relationship with a pending credential rotation removes both current and pending cached trust. |
| DR-019 | DR promotion lineage inheritance | Fixed in current PoC tree | `../openbao-dr-promotion-lineage-inheritance` | Promotion lineage records now inherit stale primary cluster IDs, relationship IDs, and secondary certificate fingerprints from earlier promotions. This prevents repeated promote -> reseed -> promote cycles from forgetting older stale authorities and accepting their old activation tokens or secondary credentials later. |
| DR-020 | DR promoted-authority reseed | Fixed in current PoC tree | `../openbao-dr-secondary-reseed-cursor-reset` | Re-enabling a non-promoted secondary against a promoted authority could retain the old lineage's persisted checkpoint high-water cursor. If the promoted authority's checkpoint index was lower, initial reconciliation failed forever with `checkpoint_index is lower than highest committed`. Secondary disable/enable now clears the local checkpoint cursor so fresh promoted-authority activation starts from the new lineage. |
| DR-021 | DR tuning validation | Fixed in current PoC tree | `../openbao-dr-tuning-validation` | DR tuning API inputs could be applied without a complete validation pass, including signed API integers flowing into unsigned byte/entry budgets. Invalid tuning now fails before persistence or runtime apply, cross-field budget/backpressure constraints are enforced, and failed manager/API updates roll back without partial in-memory mutation. |

## Notes

- Baseline HA bugs are not DR protocol bugs, but they can block DR validation
  because DR secondaries run as HA raft clusters and the tests restart them.
- Keep external harness fixes out of OpenBao worktrees unless they become
  reusable test assets in `scripts/dr-stress`.
- Before opening review, split the current PoC tree by the suggested worktree
  groups and retest each group independently.
